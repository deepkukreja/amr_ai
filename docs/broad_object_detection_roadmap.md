# AMR object detection roadmap

**Decision.** Benchmark the existing pretrained COCO checkpoint on the objects we care about, with the current rider and warehouse detectors as specialist comparisons. Collect and label the gaps before fine-tuning one compact detector. Keep the specialists as controls and compare any unified candidate against them before promoting it.

The target is reliable coverage for the objects encountered at our warehouses and outdoor sites. Recognition supplies descriptions for operators and logs. Independently, depth/LiDAR observation and the local motion supervisor handle obstacles and movement decisions. An object can occupy space even when the camera cannot assign a class. An absent or stale camera detection supplies no evidence of clearance. See the [Nav2 obstacle layer](https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/core_servers/costmap_2d/costmap_plugins/obstacle/).

## What to label first

| Priority | Working label set | Practical boundary |
|---|---|---|
| Core people and traffic | Person on foot, rider, bicycle, motorcycle/scooter, car, light commercial van, heavy road truck and bus | Decide if van and car need distinct downstream behavior. Group them for the first pass if van support is sparse. Train a scooter with motorcycle only after reviewing local examples and recording that mapping. |
| Warehouse | Forklift, pallet jack/cart, pallet, rack/shelf, bins/totes and boxes or palletized loads | Start with the distinctions that affect operator decisions. Split pallet jack from cart or box from load as data supports it. Record how nested objects such as a loaded pallet are boxed. Do not reuse a combined forklift/truck label as forklift ground truth without reviewing it. |
| Outdoor animals and site objects | Dog, cat, and cattle first if present at target sites. Add goats, birds or other locally relevant animals according to footage and failure risk. Include cones or barriers where they affect the operating area. | Report a coarse animal group in the operator UI if species confidence is poor. Give rare or unseen obstacles geometric occupancy and an unknown semantic label when appropriate. Keep birds on the ground and small animals as explicit test cases. |

Freeze a short label guide before annotation. Use `rider` for the **human** on a two-wheeler and a separate box for the bicycle or motorcycle. Clarify cyclists, passengers, standing beside a bike, and occlusion. The existing road guide includes motorcycle/scooter passengers and permits some overlap with the vehicle in the rider box. Preserve those source annotations and review affected boxes before applying the new convention. Start with distinct pedestrian/rider labels for training. Downstream, group both under human and retain rider state where useful. A person near a parked bike alone should never become a rider. Inspect duplicate person/rider predictions and test association and ambiguity on video before adding tracking rules.

## Data and model choices

- **Core road and animals.** Use the local COCO checkpoint for the initial baseline. Benchmark local footage for scooters, partially visible people, unusual vans and animals. Open Images offers box annotations for 600 categories and can fill specific gaps. Check the actual classes, hierarchy, annotation completeness, and each selected image's rights. [Open Images data and licenses](https://storage.googleapis.com/openimages/web/factsfigures_v7.html)
- **Riders and traffic.** Use the existing reviewed Indian-road inputs for development and compare label conventions with BDD100K, which includes rider and separate bicycle/motorcycle categories. BDD100K is useful for diverse road examples if its data terms fit the intended use. The toolkit license and dataset terms are separate. [BDD100K paper](https://arxiv.org/abs/1805.04687) · [Official labels](https://github.com/bdd100k/bdd100k/blob/master/bdd100k/label/label.py) · [Dataset terms guidance](https://github.com/bdd100k/bdd100k/discussions/130)
- **Warehouse.** Use the current V6 as a baseline and review missed forklift, pallet, and cart examples on the actual AMR camera. TorWIC is relevant to shelves, carts, and warehouse vehicles. Verify which labels in each source are model-derived or human-provided and review them before admitting them as reference annotations. [TorWIC source](https://github.com/Viky397/TorWICDataset)
- **Unusual categories.** Try prompted YOLOE offline as an annotation aid when regular models miss classes. Have reviewers check missing objects, false positives, and synonyms before accepting boxes. A prompt can propose an object name but rider roles and long-tail reliability still require validation. Measure the fixed-label model first on the robot. [YOLOE paper](https://arxiv.org/abs/2503.07465) · [Vendor deployment notes and limitations](https://docs.ultralytics.com/models/yoloe/#limitations)
- **Release rights.** Record dataset access terms, image provenance, permission to use footage, code/weight licenses, and approval for the intended distribution. Resolve Ultralytics licensing before choosing it for a shipped product. If its terms do not fit the intended release, evaluate a second family on the same benchmark. YOLOX's repository is Apache-2.0 and is one baseline option. Check the selected weights and training data separately. [Ultralytics licensing](https://www.ultralytics.com/license) · [YOLOX repository](https://github.com/Megvii-BaseDetection/YOLOX)

## Roadmap and evidence required

| Stage | Work | Ready to move on when |
|---|---|---|
| 1. Freeze the benchmark | Make a first reviewed **120–180 frame planning target** across warehouse aisles/loading areas, outdoor yards/roads, and low-light or partial-view scenes. Sample by distinct session. Include empty frames and lookalikes such as parked bikes, posters, metal reflections, and empty racks. Keep the earlier 166-image road set for continuity. Group all frames from the same clip, site/session, or near-duplicate cluster together. Freeze a new site/session holdout before tuning and report results with counts. | Label definitions, source and split manifests, per-class support, and label QA are recorded. Poorly represented classes stay visibly provisional. This first set measures gaps and does not establish deployment readiness. |
| 2. Compare existing weights | Run COCO with the chosen class allowlist, the current road reference/candidate, and warehouse V6 on the same reviewed examples. Compare only the classes each actually emits. If a combined view is useful, test a fixed site profile and scoped per-model mappings, keeping model identity and recording how duplicates are handled. Start on the laptop. | Per-class precision/recall, AP50–95 and misses by site, size/range, lighting and occlusion identify the training priorities. Record FPS/end-to-end latency for the combined view if it is run. |
| 3. Fill the biggest gaps and train | Review uncertain cases by session, target frequent or high-consequence misses, and collect more distinct clips rather than adjacent frames. Use licensed public examples as supplements. Rehearse existing high-value classes during fine-tuning to check for regressions. Fully label target objects in imported frames or use an explicitly validated partial-label training path, so an unlabeled truck or person is not treated as background. Train a compact unified candidate from a broad pretrained baseline only after the labels are ready. | On the frozen validation split, the candidate improves the missing classes without an unacceptable regression in person/rider and other priority classes. Compare with the unmodified baseline and specialist models. Choose operating thresholds on validation only. |
| 4. Verify on the target robot | Validate checkpoint/export parity and measure sustained Jetson throughput, capture-to-output p50/p95 latency, memory, temperature, dropped frames, and stale updates. Trace a detection through ROS to the final fleet view using semantic class, confidence, original time/frame, source/checkpoint, and optional depth or track identity with uncertainty. Replay missing depth, stale camera, and unsupported labels before running the candidate in read-only field evaluation. | The camera-to-operator path and failure behavior pass, measured results meet a compute budget agreed for the target device, and the independent field holdout confirms the intended operating envelope. Review safety and motion integration under its separate local process. |
| 5. Expand based on misses | Review hard examples from target sites. Add a category only when the distinction matters and there is enough independent evidence to train and evaluate it. Keep a rollback checkpoint, model version, and label-map version. | Each promoted version has a reproducible evidence bundle, an approved rollout path, and a clear capability list for the dashboard and website. |

For the benchmark, report recall at fixed operating thresholds, false positives per frame or minute, and counts alongside scores. Record the reporting context. A 2D box match and a usable range estimate are separate measurements. Measure latency under the intended combination of sensors, not just detector kernel speed. Use the broad baseline first to establish achievable budgets before setting numeric release targets. Keep final user-facing surfaces aligned with the [Robot Buildworks theme](../design/README.md). The benchmark needs no new interface.

**First implementation milestone.** Produce the label guide and a versioned benchmark manifest, then publish an unmodified broad COCO versus existing specialists report. That report decides whether to spend the first annotation and training pass on low/partial people, two-wheeler/rider separation, warehouse equipment, or locally common animals.
