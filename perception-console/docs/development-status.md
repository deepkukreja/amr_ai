# Development status

## Usable baseline

- The source adapter emits eleven deterministic scenarios, including the outdoor loading yard. Simulated planar rays with synthetic height samples produce the cloud and occupancy. Actor observations represent synthetic geometric clusters and aligned-depth detections. The fixture applies timestamp/frame checks, spatial association, track IDs, velocity, missed-observation expiry and independent source freshness.
- The view uses React and Three.js with one source selector, shared viewport and a tabbed inspector. Robot cosmetics and the fixture footprint depict the existing D3 concept dimensions. Unknown model identity uses a heading marker. Planned, local, predicted and traveled paths are separate channels.
- The loopback bridge serves a bounded read-only stream and scenario playback. The Gazebo adapter reads the existing nominal-91 capture and map where available. It derives 240 display samples over 47.8 seconds with five waypoint markers. It preserves source pose timestamps, shows measured wheel speed and recorded covariance where present, and leaves unavailable inputs blank. It reads existing artifacts in place.

## Verification evidence

On 22 November 2026, `npm test` passed 11 automated tests. Checks cover timestamps, frame transforms, occupancy, classification fallback, track continuity and expiry, the 11 scenarios, indoor/outdoor source isolation, replay, PGM conversion and loopback transport restrictions. `npm run build` completed. Vite reported a large client bundle and ignored client-only directives from the icon library.

The in-app browser showed the D3 scene and source state in the warehouse and at the outdoor loading yard. The desktop viewport was verified at 1440 × 900 and the mobile shell at 390 × 844. The browser check exercised source switching, view freeze, semantic object selection, occupancy view, the LiDAR-loss event with a stale sensor and cleared cloud, and the Gazebo route replay including seek to the final waypoint, restart, speed adjustment and play/pause. The narrow viewport was corrected so the canvas fills the world panel.

The existing ONNX export at SHA-256 `8deda79dc51facf20262c8d1a3a5457d413c60a589a32e85e8716b1116d9f2d0` ran in the existing WSL ONNX Runtime 1.32.0 environment with the CPU provider. One local validation image was resized and letterboxed as FP32 RGB NCHW `[1,3,512,960]`. The graph returned finite `[1,6,10080]` values and the expected person and rider metadata. This checks runtime and tensor compatibility. Detector quality and deployed thresholds use the upstream validation and calibration process. The browser scenario classifications are generated by the simulation adapter.
