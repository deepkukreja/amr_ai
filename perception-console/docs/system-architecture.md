## Data flow and deployment

1. Onboard maintained drivers publish stamped ROS observations. Per-sensor IDs, topics, frame IDs, timestamp basis, extrinsics, calibration versions, QoS, expected rates and freshness thresholds come from deployment configuration. Time sync and motion compensation use sensor-specific capabilities and the timestamped pose buffer.
2. Existing filters and detector emit geometry and semantic measurements. Match calibrated depth and image timestamps, project using CameraInfo, transform at acquisition time and associate by geometry and compatible uncertainty. Keep classification and geometry confidence separate. A failed classification leaves its geometric obstacle available. Reuse existing depth fusion and obstacle processing first.
3. Local world state retains occupancy, tracked objects, robot pose, trajectories and per-source health as independently updated channels. Use `odom` for short-horizon tracking and `map` for registered/global pose and global paths, preserving frame IDs and uncertainty across localization corrections. Time-aligned snapshots provide a versioned view. Missing transforms leave the affected channel unavailable. Local navigation continues to consume validated ROS topics/costmaps and the local supervisor. [REP-105](https://github.com/ros-infrastructure/rep/blob/master/rep-0105.rst) · [Jazzy QoS](https://github.com/ros2/ros2_documentation/blob/jazzy/source/Concepts/Intermediate/About-Quality-of-Service-Settings.rst)
4. The edge gateway owns read-only projections of that state. Downsample point clouds, cap queues and avoid video in telemetry JSON. Local processing and protective behavior run without browser or WAN. Authenticated remote monitoring belongs in the fleet platform. Preserve the current V1 fleet robot report and add a separate world stream. Use compact binary cloud frames and bounded channel budgets when measured traffic warrants them.
5. Use React for the console, matching the fleet frontend stack. Use Three.js directly inside one viewport component to own buffers, layer lifetime and project labels. React Three Fiber adds a scene reconciliation layer that this imperative stream consumer can defer. Existing RViz remains available to engineers, and a later Foxglove adapter can expose the same state as standard scene/point schemas. Use rosbag2/MCAP for stamped robotics capture and a smaller indexed world-frame playback format for the browser. [Three.js](https://github.com/mrdoob/three.js) · [React Three Fiber](https://github.com/pmndrs/react-three-fiber) · [Foxglove SceneUpdate](https://docs.foxglove.dev/docs/sdk/schemas/scene-update) · [MCAP storage plugin](https://github.com/ros2/rosbag2/tree/jazzy/rosbag2_storage_mcap)

## Implementation order

1. **Independent vertical slice.** Add `server/` for deterministic indoor and outdoor measurements, stamped geometry/semantic fusion, track lifecycle, occupancy, read-only stream and recorded world frames. Add `src/` for the shared React operator screen, its Three.js viewport, six visualization modes, source and navigation state, replay and diagnostics. Add `tests/` for frame validity, unknown-space behavior, source switching, dropout, tracking, replay and HTTP transport. Use a browser check to verify rendered frames and operator interactions. [Operator view research](operator-view-research.md)
2. **Existing-source integration.** Add a read-only ROS adapter using current topics and TF, initially exercised with the validated Gazebo world in an approved unused ROS domain. Reuse upstream 2D/3D detections and current filtered cloud. Register the current map plus version from the map owner. Verify source timing, units, covariance, backpressure and stale reporting. Land the view as a scoped route in `amr_platform` after coordination. Current Git state precludes safely basing this work on committed copies of the shared in-progress features.
3. **Broader perception.** Evaluate runtime candidates against warehouse person/forklift/cart coverage. Extend the existing geometric path with deskew, terrain/slope/clearance classification, track association and uncertainty. Validate curbs, ramps, low and hanging obstacles, drop-off evidence, outdoor glare and sensor blind zones with fixtures and labeled captures. Keep terrain with missing returns unknown.
4. **Operations.** Add synchronized RGB/depth views, overlay projection and timing, map selection/quality and mission history in the existing platform. Measure CPU/GPU, memory, cloud bandwidth and end-to-end video/frame age before choosing transport or compute. Use an authenticated monitoring channel and test remote control only in an isolated simulation until the local supervisor and physical protective functions are reviewed.

Build the increment in a scoped Windows directory because the coordination checkout has no commit to base a worktree on and the upstream worktrees already have unrelated changes. Publish the perception slice under its own branch in the configured `amr_ai` source repository. The fleet checkout has no configured remote. The console is a development adapter for the eventual fleet view. Its bridge runs on loopback and requires neither ROS nor an actuator interface.
